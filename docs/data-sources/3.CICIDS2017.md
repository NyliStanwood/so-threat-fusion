# CICIDS2017

**Full name:** Canadian Institute for Cybersecurity Intrusion Detection Evaluation Dataset 2017  
**Institution:** Canadian Institute for Cybersecurity (CIC), University of New Brunswick  
**Dataset page:** https://www.unb.ca/cic/datasets/ids-2017.html  
**Published:** 2017  
**License:** Free for research/academic use — requires registration to download

---

## Overview

A benchmark network intrusion dataset generated in a controlled lab environment over five days (July 3–7, 2017). It contains both realistic background traffic (simulated user behaviour: browsing, email, FTP, SSH) and labelled attack traffic across eight attack categories.

Unlike Malware Traffic Analysis PCAPs (real malware, no labels embedded) or EVTX-ATTACK-SAMPLES (host events, no network), CICIDS2017 provides:

- **Raw PCAPs** for replaying into SO's monitoring interface
- **Pre-labelled CSV files** with per-flow ground truth (attack type per flow)

The combination makes it directly usable for Phase 5 evaluation: replay the PCAP → SO generates Zeek/Suricata events → fusion engine clusters them → compare cluster ATT&CK tags against the CSV ground truth labels.

**Widely cited** — one of the most referenced benchmark datasets in IDS/ML research. Many published papers report detection rates on it, giving you a comparison baseline for the thesis evaluation chapter.

## Dataset Structure

### Five-day capture schedule

| Day | Traffic | Attack types |
|---|---|---|
| Monday | Benign only | None — pure background traffic baseline |
| Tuesday | Benign + attacks | Brute Force: FTP-Patator, SSH-Patator |
| Wednesday | Benign + attacks | DoS: Slowloris, Slowhttptest, Hulk, GoldenEye; Heartbleed |
| Thursday | Benign + attacks | Web attacks: Brute Force, XSS, SQL Injection; Infiltration |
| Friday | Benign + attacks | Botnet (ARES), Port Scan, DDoS (LOIT) |

### File types

| Format | Contents | Size |
|---|---|---|
| `.pcap` per day | Raw packet capture | ~50 GB total (~11 GB Monday alone) |
| `.csv` per day | Pre-extracted flow features + `Label` column | ~750 MB total |

The CSV files are the ground truth. The `Label` column contains values like `BENIGN`, `FTP-Patator`, `DDoS`, `Web Attack – SQL Injection`, etc.

## Technical Details

### PCAP files

Same format as any libpcap capture — directly replayable with `tcpreplay`. The traffic was generated between a victim network (172.16.0.0/12) and an attack machine. All five days are separate files so you can select specific attack types without replaying the full dataset.

### CSV feature files (CICFlowMeter output)

The CSVs contain ~80 bidirectional flow-level features extracted by **CICFlowMeter**, UNB's flow analysis tool. Each row is one network flow.

Key columns:

| Column | Description |
|---|---|
| `Flow ID` | Source IP, Dest IP, Source Port, Dest Port, Protocol |
| `Source IP` / `Destination IP` | Flow endpoints |
| `Flow Duration` | Duration in microseconds |
| `Total Fwd Packets` / `Total Backward Packets` | Packet counts per direction |
| `Flow Bytes/s` / `Flow Packets/s` | Rate features |
| `Label` | Ground truth: `BENIGN` or attack name |

These features are computed from the PCAP — they are **not** raw event logs. They won't appear in SO directly. Their value is as a lookup table: given a flow (src IP, dst IP, ports, time), find its label in the CSV.

### Traffic generation methodology

- **Benign traffic:** B-Profile system — models real user behaviour (web browsing, email, FTP, SSH, downloads) using user profiles; not random noise
- **Attack traffic:** Executed from a Kali Linux attacker VM against a victim network running Windows Vista/7/8.1/10 and Ubuntu servers
- **Capture point:** On the router between victim and attacker networks — captures both directions of every flow

## Ingestion into Security Onion

### Path 1 — Replay PCAPs with tcpreplay (recommended)

Same process as Malware Traffic Analysis PCAPs. Replay on Kali's `eth1` → SO's monitoring interface captures it → Zeek and Suricata generate events.

```bash
# On Kali — replay Wednesday (DoS attacks) at controlled rate
sudo tcpreplay --mbps=10 -i eth1 Wednesday-WorkingHours.pcap
```

**Then in SO Hunt:**
```
event.dataset: suricata.alert
event.dataset: zeek.conn
```

> **Warning:** These PCAPs are large (up to 11 GB per day). Replay at `--mbps=10` or lower. Full-speed replay will flood SO's ingestion pipeline and cause dropped packets. Wednesday and Friday are the most useful days for thesis scenarios — replay those first.

### Path 2 — Use CSVs as ground truth labels only (no PCAP replay needed)

If you only need the label data for evaluation (not live SO event generation), parse the CSVs directly:

```python
import pandas as pd

df = pd.read_csv("Wednesday-WorkingHours.pcap_ISCX.csv")
# Normalise column names (they have leading spaces in some versions)
df.columns = df.columns.str.strip()

# Count attack types
print(df["Label"].value_counts())

# Extract only attack flows
attacks = df[df["Label"] != "BENIGN"]
print(attacks[["Source IP", "Destination IP", "Label"]].head(20))
```

### Path 3 — Cross-reference SO events against CSV labels

This is the evaluation workflow for Phase 5:

```
1. Replay PCAP into SO
2. Query SO Elasticsearch for Zeek conn events in that time window
3. For each Zeek flow (src_ip, dst_ip, src_port, dst_port), look up the label in the CSV
4. Check whether fusion engine tagged the cluster with the correct ATT&CK technique
5. Label match = true positive; miss or wrong tag = false negative / false positive
```

The CSV gives you the ground truth at flow granularity; the fusion engine works at cluster granularity. Mapping between them is the evaluation logic for the thesis results chapter.

## Timestamp Handling

Same issue as MTA PCAPs — all timestamps are from July 2017. Use `editcap` to shift to today before replaying:

```bash
# Shift Wednesday PCAP from 2017 to today
# First check the first packet timestamp
capinfos -a Wednesday-WorkingHours.pcap

# Calculate offset in seconds: today_epoch - first_packet_epoch
# Then shift:
editcap -t <offset_seconds> Wednesday-WorkingHours.pcap Wednesday-now.pcap

# Replay the shifted file
sudo tcpreplay --mbps=10 -i eth1 Wednesday-now.pcap
```

If you use the CSVs for ground truth cross-referencing without PCAP replay, timestamps don't matter — just query SO with a wide time window.

## Recommended Days to Start With

| Priority | Day | Why |
|---|---|---|
| 1 | **Wednesday** | DoS attacks — high-volume, easy to detect, Suricata fires reliably; Heartbleed is interesting for the thesis (vulnerability exploitation) |
| 2 | **Friday** | DDoS + Port Scan + Botnet — three distinct attack categories in one PCAP, good for multi-stage fusion |
| 3 | **Tuesday** | Brute force — clean, simple; good for verifying SO ingestion is working before trying complex scenarios |
| 4 | **Thursday** | Web attacks (XSS, SQLi) — application-layer; tests Suricata HTTP rules |
| Skip | **Monday** | Benign only — useful for establishing a false positive baseline but not for detection scenarios |

## Known Limitations (relevant for the thesis)

These are documented in the academic literature and worth acknowledging in the evaluation chapter:

- **Artificial background traffic** — the B-Profile benign traffic does not fully replicate real enterprise behaviour; some ML models overfit to its patterns
- **Label noise** — several researchers have found mislabelled flows (benign flows labelled as attacks and vice versa) in the CSV files; estimated ~0.1–1% error rate depending on the day
- **No encryption** — most traffic is unencrypted; modern malware uses TLS for C2, which this dataset does not represent well
- **Isolated lab network** — no internet routing, no NAT, no real DNS resolution; replayed traffic will look slightly different in a real SO deployment
- **Static attack timing** — attacks happen at predictable intervals within each day file; a real attacker would vary timing to evade time-window correlation

Citing these limitations shows awareness of dataset validity — it strengthens the thesis evaluation chapter rather than weakening it.

## Tools Reference

| Tool | Purpose | Notes |
|---|---|---|
| `tcpreplay` | Replay PCAPs onto `eth1` | Use `--mbps` flag for large files |
| `editcap` | Timestamp shifting, PCAP splitting | `editcap -A <start> -B <end>` extracts a time slice |
| `capinfos` | PCAP metadata summary | Check duration and first/last timestamps before replaying |
| `pandas` | Parse and query the CSV label files | `pip install pandas` |
| CICFlowMeter | Re-extract features from custom PCAPs | Java tool; use if you generate your own traffic and want matching CSV features |
| `tshark` | Filter specific attack flows from large PCAPs | `tshark -r file.pcap -Y "ip.src == 172.16.0.1"` |
