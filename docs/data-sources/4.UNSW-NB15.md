# UNSW-NB15

**Full name:** UNSW Network Benchmark 2015  
**Institution:** Cyber Range Lab, University of New South Wales (UNSW) Canberra  
**Principal researcher:** Nour Moustafa, supervised by Jill Slay  
**Dataset page:** https://research.unsw.edu.au/projects/unsw-nb15-dataset  
**Published:** 2015–2016  
**License:** Free for academic/research use

---

## Overview

A benchmark network intrusion dataset generated in a controlled cyber range lab at UNSW Canberra over 31 hours across two capture sessions (January 22 – February 2, 2015). Traffic was generated using **IXIA PerfectStorm** — a professional traffic generation appliance — giving it more realistic flow characteristics than datasets built with simple scripts.

It covers **nine attack categories** and provides both raw PCAPs and pre-extracted CSV feature files with per-flow ground truth labels.

**Why this matters for this project:**

UNSW-NB15 is the most commonly used modern alternative to the ageing KDD99/NSL-KDD datasets. Its attack categories (Exploits, Shellcode, Backdoors, Reconnaissance) map more cleanly to ATT&CK tactics than CICIDS2017's categories, making it better suited for the fusion engine's ATT&CK tagging layer. The pre-built training/testing CSV splits also make it convenient for quantitative evaluation in the thesis results chapter.

---

## Attack Categories

Nine categories spanning both network-layer and application-layer attacks:

| Category | Description | ATT&CK mapping |
|---|---|---|
| **Exploits** | Software vulnerability exploitation | Execution, Initial Access |
| **Fuzzers** | Sending random/malformed input to crash or probe services | Discovery, Reconnaissance |
| **Reconnaissance** | Port scanning, service fingerprinting, network mapping | Discovery |
| **DoS** | Denial of service traffic flooding a target | Impact |
| **Backdoors** | Remote access maintained after initial compromise | Persistence, C2 |
| **Analysis** | Port scans, spam, HTML injection probes | Discovery, Initial Access |
| **Shellcode** | Shellcode injection attempts | Execution, Privilege Escalation |
| **Worms** | Self-propagating malware traffic | Lateral Movement |
| **Generic** | Attacks on block cipher keys — protocol-agnostic | Defense Evasion |

## Dataset Structure

### Raw PCAPs

| File | Contents |
|---|---|
| `UNSW-NB15_1.pcap` | Capture session 1 — benign + mixed attacks |
| `UNSW-NB15_2.pcap` | Continuation |
| `UNSW-NB15_3.pcap` | Continuation |
| `UNSW-NB15_4.pcap` | Capture session 2 |

Total raw PCAP size: ~100 GB. Download selectively — start with one file.

### CSV feature files

| File | Contents |
|---|---|
| `UNSW-NB15_1.csv` – `UNSW-NB15_4.csv` | Full feature set, one row per flow, matching each PCAP |
| `UNSW_NB15_training-set.csv` | Pre-split training partition (~175k records) |
| `UNSW_NB15_testing-set.csv` | Pre-split testing partition (~82k records) |
| `UNSW_NB15_GT.csv` | Ground truth table — flow ID → attack category |
| `UNSW-NB15_features.csv` | Feature name + description reference |

The training/testing split is pre-defined by the authors, which is useful when comparing your results against published papers — everyone uses the same split.

## Technical Details

### Feature extraction pipeline

Unlike CICIDS2017 (which uses CICFlowMeter exclusively), UNSW-NB15 features were extracted using a combination of tools:

| Tool | Features extracted |
|---|---|
| **Argus** | Basic flow features: duration, protocol, state, bytes, packets |
| **Bro/Zeek scripts** | Content features: HTTP method, FTP commands, DNS query count |
| **Custom analysis** | Time-series features: connection rate, TTL-based state features |

This matters because the CSV features are closer to what Security Onion already generates (Zeek logs → Elasticsearch) than a purely synthetic feature set. The overlap means you can cross-reference SO's Zeek output against UNSW-NB15 CSV columns more directly.

### 49 features — key groups

| Group | Example features | Count |
|---|---|---|
| Basic flow | `dur`, `proto`, `service`, `state`, `spkts`, `dpkts`, `sbytes`, `dbytes` | 9 |
| Content | `land`, `wrong_fragment`, `urgent`, `hot`, `num_failed_logins` | 5 |
| Time-based | `count`, `srv_count`, `serror_rate`, `rerror_rate` | 13 |
| Connection | `ct_state_ttl`, `ct_flw_http_mthd`, `ct_ftp_cmd`, `ct_srv_src` | 10 |
| Label | `attack_cat`, `label` (binary: 0=normal, 1=attack) | 2 |

`attack_cat` is the ground truth string (e.g. `Exploits`, `Backdoor`, `Reconnaissance`).  
`label` is the binary version — useful for simple detection rate metrics.

### Network topology used during capture

```
[Attack VM] ←→ [Router] ←→ [Victim network: 175.45.176.0/24 – 175.45.179.0/24]
                   ↑
            [Capture point]
```

Victim IPs are in the `175.45.176.0/22` range. When you replay PCAPs into SO, Zeek will log these IPs — use them to filter relevant events.

## Quick Access via Kaggle (CSV only, no PCAPs)

The CSV files are available on Kaggle without needing to register with UNSW directly. Search Kaggle for **"UNSW-NB15"** — several community uploads exist with the full 49-feature files and the training/testing splits. The PCAPs are only available from the UNSW research page (requires registration).

**Use Kaggle CSVs if:**
- You want the ground truth labels for evaluation logic without replaying 100 GB of traffic
- You want to prototype the Phase 5 evaluation pipeline before committing to full PCAP replay

**Use UNSW PCAPs if:**
- You need SO to generate real Zeek/Suricata events from this traffic
- You want to test whether SO's detection fires on UNSW-NB15 attack categories

## Ingestion into Security Onion

### Replay PCAP with tcpreplay

Same workflow as CICIDS2017 and MTA PCAPs:

```bash
# Start with the smallest file — check sizes first
ls -lh UNSW-NB15_*.pcap

# Inspect before replaying
capinfos UNSW-NB15_1.pcap
tshark -r UNSW-NB15_1.pcap -q -z conv,ip | head -30

# Replay at controlled rate — these files are large
sudo tcpreplay --mbps=10 -i eth1 UNSW-NB15_1.pcap
```

In SO Hunt after replay:
```
event.dataset: zeek.conn AND destination.ip: 175.45.176.0/22
```

The victim subnet `175.45.176.0/22` scopes results to UNSW-NB15 traffic only.

### Timestamp shifting

All packets are from January–February 2015. Shift to today with editcap:

```bash
capinfos -a UNSW-NB15_1.pcap   # get first packet timestamp
# Calculate offset = today_epoch - first_packet_epoch
editcap -t <offset_seconds> UNSW-NB15_1.pcap UNSW-NB15_1-now.pcap
sudo tcpreplay --mbps=10 -i eth1 UNSW-NB15_1-now.pcap
```

## Comparison with CICIDS2017

| Property | UNSW-NB15 | CICIDS2017 |
|---|---|---|
| Attack categories | 9 (Exploits, Backdoors, Worms, etc.) | 8 (DDoS, Brute Force, Web attacks, etc.) |
| ATT&CK mapping | Cleaner — categories align with ATT&CK tactics | Looser — technique-named but less tactic-aligned |
| Traffic generation | IXIA PerfectStorm (professional) | B-Profile + manual tools (scripted) |
| Feature extraction | Argus + Zeek + custom | CICFlowMeter only |
| Pre-built train/test split | Yes — standardised split | No — you split yourself |
| Raw PCAP size | ~100 GB | ~50 GB |
| CSV size | ~750 MB | ~750 MB |
| Published label noise issues | Fewer reported | More reported |
| Best use | ATT&CK mapping evaluation, benchmarking | Time-series/volume-based attack evaluation |

Both datasets are worth using: CICIDS2017 for its day-separated attack categories (easy to isolate one attack type), UNSW-NB15 for its cleaner ATT&CK alignment and standardised evaluation split.

---

## Known Limitations

- **No application-layer content** — encrypted or application payloads are not included in extracted features; the dataset predates widespread TLS adoption in C2 traffic
- **Static IP ranges** — victim IPs (`175.45.176.0/22`) and attacker IPs are fixed; easy for ML models to learn the topology rather than the attack behaviour
- **Lab environment only** — no internet routing, no DNS resolution against real resolvers, no CDN traffic
- **2015 attacks only** — no ransomware, no supply chain, no cloud-targeted attacks; represents the threat landscape of that era
